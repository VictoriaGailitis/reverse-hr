# Локальная проверка Runner — 10 октября 2026

Рабочий узел: `reverse-hr-runner-native`, Ubuntu 24.04 ARM64 в OrbStack.
Постоянный UUID: `ace8bdf6-270f-4715-b28c-43d2482254b3`.

- Подключён к существующей PostgreSQL БД Code Runner; режим `execution`, версия 2.
  При переключении не было неочищенных попыток.
- Работают три очереди: execute, validate, grade-tests. Подготовка и сбор материалов
  Evaluation, outbox и consumers Assessment/Workspace/Runner/Evaluation также запущены.
- RabbitMQ: по одному consumer на каждой из четырёх incoming очередей.
- Внутренние API Privacy/Assessment/Workspace/Evaluation возвращают readiness 200
  через локальный mTLS-туннель. Host/LAN port bindings отсутствуют.
- Проверены подписи реального запроса и ответа Privacy и подписанного отказа
  Assessment для отсутствующего набора: несуществующий набор не получает допуск.
- Все 12 реальных проверок изоляции пройдены после подключения к платформе.
  Дополнительный реальный тест закреплённого синтетического набора выполнил шесть
  запусков в NsJail: эталон прошёл, оба ошибочных алгоритма обнаружены.
- Приватные signing key, client TLS key и конфигурация имеют права 0600.
  VM получает только свой клиентский TLS ключ; серверный ключ и ключ CA в неё
  не передаются. Сервер требует mTLS 1.3 и точный отпечаток клиентского сертификата.
- Systemd запускает Runner и клиент туннеля при старте VM. Refresh timer повторяет
  probes каждые 12 часов. Неуспешные или просроченные probes закрывают исполнение.

Текущий проверенный runtime допущен в Assessment на семь дней. Изменение исходников,
артефактов, kernel или области cgroup требует новой проверки и явного обновления
допуска; политика не продлевается автоматически. TLS-сертификаты действуют 30 дней.

Воспроизводимые инструкции: [README](README.md). Конфигурация Docker-моста:
[compose.runner-orbstack.yaml](../../compose.runner-orbstack.yaml).

Проверки соединения и очередей не заменяют отдельный пользовательский прогон
сессии через браузер с реальными настройками авторизации и оценки LLM.
