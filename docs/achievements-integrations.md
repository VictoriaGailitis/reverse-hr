# Achievements, демоисточники и ATS

Backend-инкремент от 9 октября 2026. Achievements владеет нормализованными
достижениями, привязками и доверием. Integration владеет транспортом,
журналом доставки, повторами и внешними статусами. `demo-fsp`,
`demo-codenrock` и `demo-ats` — отдельные подписывающие сервисы с отдельными БД.
Это работающий обмен между компонентами на синтетических данных.
Контракты реальных ФСП/Codenrock/ATS не предполагаются.

## Достижения и права

Все пути ниже относительны публичному API Achievements; gateway использует
префикс `/achievements`. Команды требуют JWT и `Idempotency-Key`, изменения
версий — `If-Match`. Runtime OpenAPI находится в `contracts/achievements.openapi.json`.

| API | Назначение |
|---|---|
| `GET /v1/achievement-sources` | Реестр адаптеров и возможностей |
| `POST /v1/achievement-sources` | Регистрация источника администратором с MFA |
| `PUT /v1/achievement-sources/{id}/enabled` | Приостановка/возобновление источника |
| `POST /v1/achievement-connections` | Привязка кандидатом с согласием на импорт |
| `POST /v1/achievement-link-confirmations` | Подтверждение связи партнёром своего источника |
| `GET /v1/achievement-connections/me` | Свои связи, дата и состояние синхронизации |
| `POST /v1/achievement-connections/{id}/disconnect` | Отключение и скрытие результатов |
| `POST /v1/achievements/declared` | Непроверенное самоописание кандидата |
| `GET /v1/achievements/me` | Свои достижения, UUID cursor, до 50 записей |
| `PUT /v1/achievements/{id}/visibility` | Публикация по отдельному согласию |
| `POST /v1/achievements/{id}/review` | Независимая проверка человеком с MFA и причиной |
| `GET /v1/achievements/{id}/review` | Разрешённые исходные сведения для независимого проверяющего |
| `GET /v1/achievements/{id}/history` | История владельца, до 100 записей |
| `PUT /v1/achievements/{external_id}` | Партнёр создаёт/обновляет свой результат |
| `POST /v1/achievements/{external_id}/revoke` | Партнёр отзывает свой результат |
| `POST /v1/achievement-imports` | Асинхронный пакет до 100 результатов |
| `GET /v1/achievement-imports/{id}` | Собственный статус и ошибки по записям |

Роли: `integration_admin`, `achievement_partner`, `achievement_moderator`.
Источник партнёра определяется по OIDC subject, закреплённому администратором.
Партнёр не передаёт произвольный candidate ID: его внешний аккаунт должен
соответствовать уже подтверждённой связи. Для реального источника кандидат
создаёт pending-связь, партнёр подтверждает её в течение десяти минут;
проверяются текущая версия, согласие и уникальность аккаунта. Демо-связь явно
обозначена и выдаётся сервером для текущего кандидата.

Нормализуются мероприятие, дисциплина, дата, специализация, индивидуальный/
командный формат, место, баллы, размер группы и ссылка на доказательство.
Отсутствующие значения остаются пустыми. Идентификатор записи уникален по
источнику и внешнему ID; внешний ID нельзя перепривязать к другому кандидату.
Младшие версии игнорируются, одинаковые версии с разными данными отклоняются.
Обновление реального результата возвращает его на проверку. Отзыв скрывает
публикацию; старый импорт не возвращает отозванный результат.

Статусы — `declared`, `imported_pending`, `confirmed`, `revoked`.
Полученный JSON сам по себе не подтверждает достижение. Партнёрские записи
подтверждает независимый модератор; демоданные подтверждаются только как demo.
Поле `demo` устанавливается сервером из режима окружения и не принимается от
кандидата/партнёра. Достижения не меняют профессиональный грейд.

Согласия разделены: `achievement_import` и `achievement_publication`.
Публикация и выдача Matching требуют актуальных обоих согласий, активной связи,
включённого источника и подтверждённого результата. Удаление и отключение
не требуют сохранения согласия на импорт. Подтверждённый командный результат
не получает индивидуальный бонус.

Matching включается настройкой `HR_MATCHING_ACHIEVEMENTS_ENABLED=true`
(Compose: `MATCHING_ACHIEVEMENTS_ENABLED=true`). По умолчанию выключен для
совместимости базового профиля Compose. Бонус релевантного индивидуального
результата — 2, общий максимум — 5; итоговый score ограничен 100. Совпадающие
нормализованные результаты из нескольких источников дают один вклад.
Это предварительное правило демонстрации, без заявления о калибровке весов.
В production-подборе demo исключены. Matching получает только минимальные
подписанные сведения без контактов/внешних аккаунтов; сохранённая подборка
повторно проверяет права и версии достижений.

## Синхронизация и демоисточники

`POST /integration/v1/integrations/syncs` принимает `connection_id`.
`GET /integration/v1/integrations/jobs/{id}` показывает разрешённый журнал.
Для одной связи допустима одна незавершённая синхронизация; частота ограничена
30 секундами. Пакетный партнёрский импорт ограничен десятью ожидающими заданиями.
Частичные ошибки сохраняются отдельно от корректно импортированных записей.

Worker `python -m reverse_hr.worker integrate` получает действующую связь через
подписанный Achievements API, вызывает конкретный адаптер и возвращает записи
в Achievements с версией связи. Отключение/перепривязка во время запроса не
позволяет импортировать данные по старой связи. Партнёрские пакеты обрабатывает
`python -m reverse_hr.worker achievement-import`.

`HR_DEMO_SOURCE_SCENARIO` на сервисе источника: `normal`, `empty`, `updated`,
`revoked`, `unavailable`. Пустой успешный ответ отличим от технического сбоя;
updated/revoked повышают внешнюю версию. Demo работает при
`HR_DEPLOYMENT_MODE=demo`; в production транспорт демоэкспорта блокируется.
Сценарий и режим задаёт оператор, клиент не может их изменить.

Все назначения сети заданы Settings; произвольного пользовательского URL нет.
HTTP обмен имеет раздельные контексты подписи для операции/сервиса/направления,
свежие nonce, ограничение времени и размера, привязанный к запросу ответ.
Перенаправления и системные proxy не используются. Демоисточники не имеют
публичного gateway-маршрута; `/internal/` новых сервисов закрыт gateway.

## ATS и Hiring

`POST /integration/v1/integrations/ats-exports` принимает `candidate_id`,
`organization_id`, `invitation_id`, `consent_id` цели `ats_export`.
Компания должна быть верифицирована, сотрудник — действующим, приглашение —
принятым и незаблокированным. Дополнительно необходимы опубликованный профиль
и разрешённое раскрытие контактов конкретной компании. Допуск проверяется
на постановке задания, каждой доставке и каждом чтении ATS.

Integration хранит ссылки на сущности, версии, попытки и состояние доставки.
Разрешённый профиль и контакты собираются заново перед отправкой. Задания
имеют lease 60 секунд; истёкший lease можно повторить после сбоя процесса.
Недоступность приводит к ограниченным повторам (до трёх попыток), отзыв прав —
к отмене. Сетевой запрос выполняется вне локальных блокировок задания/кандидата.

Демо-ATS хранит полученный приватный JSON, возвращает стабильный внешний UUID
для пары кандидат/организация и дедуплицирует доставки по job ID и digest.
Потеря ответа после сохранения не создаёт нового кандидата. Последовательность
доставки защищает от старого экспорта поверх нового.

| API demo-ATS | Назначение |
|---|---|
| `GET /demo-ats/v1/ats/candidates/{external_id}` | Разрешённый полученный профиль |
| `POST /demo-ats/v1/ats/candidates/{external_id}/status` | Изменение статуса с текущей версией |
| `GET /hiring/v1/invitations/{id}/ats-status` | Разрешённые внешние статусы в Hiring |

Допустимые внешние переходы: received → interview/rejected,
interview → offer/rejected, offer → hired/rejected. hired/rejected терминальны.
Worker `python -m reverse_hr.worker ats-callback` доставляет подписанные статусы
в Integration с монотонной последовательностью и ограниченными повторами.
Повтор/позднее событие не возвращает предыдущий статус. Integration публикует
событие с идентификаторами; Hiring получает свежий разрешённый результат через
подписанный API и хранит отдельную проекцию внешнего статуса. Статус ATS не
перезаписывает внутренний человеческий процесс отклика.

Отзыв `ats_export` сразу закрывает выдачу и новые доставки. Consumer затем
удаляет соответствующие данные ATS и отменяет задания. Privacy deletion
стирает привязки/достижения/историю/пакеты/кеши, доставки/обратные статусы и
данные получателя. Integration выдаёт ACK только после подписанного
подтверждения очистки ATS; сбой получателя оставляет удаление на повтор.
Постоянные tombstone не позволяют поздней доставке восстановить данные.

## Подготовка стенда

Добавлены миграции `0002_achievements`, `0002_integration`,
`0002_demo_ats`, `0002_demo_fsp`, `0002_demo_codenrock`, `0006_hiring`.
Новые БД/роли: `demo_fsp`, `demo_codenrock`, `demo_ats` с отдельными
`DEMO_FSP_DB_PASSWORD`, `DEMO_CODENROCK_DB_PASSWORD`, `DEMO_ATS_DB_PASSWORD`.
Fresh bootstrap обновлён; на существующем PostgreSQL init-скрипт автоматически
повторно не выполняется — требуется подготовить новые роли/БД и миграции.
Миграции запускаются штатным `python -m reverse_hr.migrate upgrade head`
в окружении соответствующего сервиса с его отдельным `HR_DATABASE_URL`.

Оператор должен обновить настройки окружения, ключи/доверенные публичные ключи
трёх демосервисов, роли Keycloak и RabbitMQ bindings. `configure_events.py`
сохраняет существующие signing identities и добавляет недостающие; ротация
требует согласованного обновления доверенных ключей. Скрипты конфигурации
работают с секретами и не запускались в этом инкременте.

Полный Compose профиль `all` содержит API, import/integration/callback workers,
outbox/consumers Achievements/Integration и обмен статусов Integration → Hiring.
Для bonus включите `MATCHING_ACHIEVEMENTS_ENABLED=true`. Gateway откладывает
DNS разрешение необязательных сервисов, чтобы их отсутствие не мешало
базовому профилю стартовать.

Тесты используют мигрированные отдельные SQLite БД и настоящий подписанный
RPC через TestClient, реальные обработчики очередей и workers. Live-приёмка
PostgreSQL/RabbitMQ/Compose, экраны достижений и demo-ATS, а также включение
достижений в PDF остаются отдельными работами. Реальный внешний API не подключён.
