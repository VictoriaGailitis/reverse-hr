# Менеджерские специализации

Канонические названия используются одинаково в профиле, вакансии, потребности компании, референсе и политике оценки. Кандидат может совмещать направления; подтверждённый грейд независим для каждого.

| Направление | Идентификатор | Форматы | Компетенции |
| --- | --- | --- | --- |
| Project Manager | `project_manager` | Видеоинтервью, доска | Планирование, оценка сроков, зависимости, риски, коммуникация, организация команды |
| Product Manager | `product_manager` | Видеоинтервью, доска | Исследование проблем, гипотезы, приоритеты, продуктовые метрики, эксперименты |
| Technical Manager | `technical_manager` | Видеоинтервью, доска; дополнительно небольшой код | Архитектурные компромиссы, надёжность, качество разработки, технические риски, организация команды |

Для нового менеджерского референса интерфейс предлагает видео (`vcv`). Оператор может выбрать доску (`whiteboard`), а для Technical Manager также код (`code`). Доска подходит для схем, планов, приоритетов и разбора кейсов, не только для архитектуры. Доступные форматы не ограничиваются жёстко: компания может создать собственную комбинацию.

Референсы пишутся оператором через существующий конструктор: оригинальный кейс, необходимые компетенции, ограничения вариативности, рубрика и наблюдаемые доказательства. Project Manager может разобрать срыв срока и составить план восстановления; Product Manager — предложить гипотезу, метрики и план эксперимента; Technical Manager — объяснить технический компромисс, спроектировать систему и при необходимости исправить небольшой фрагмент кода.

Управленческий грейд оценивает качество решений и обоснования. Для видео доказательства привязаны к записи, для доски — к сохранённому снимку. Необязательное задание на код проверяется Runner; оно не заменяет оценку управленческих компетенций. Состав рубрики, веса и пороги задаются в референсе и политике оценки, а не выводятся из названия роли.

Добавление направлений в интерфейс не публикует задания и не создаёт экспертную калибровку. Для запуска тестирования нужно создать референсы по нужным уровням, проверить пробную генерацию, опубликовать проверенный контент и утвердить калиброванную политику. До этого кандидат может указать направление и заявленный грейд, но подтверждённый грейд требует прохождения оценки.
