# Аналитика качества заданий

Кабинет платформы → «Качество заданий». Доступ: `content_admin` с MFA.
Аналитика описательная: расчёт не меняет грейды, рубрики, политики оценки или публикацию задания.

Для каждого junior / middle / senior / lead оператор задаёт два порога (0–100):

| Категория | Начальная шкала | Цвет |
| --- | --- | --- |
| Не решена / решена плохо | 0–49 | Красный |
| Решена нормально | 50–79 | Жёлтый |
| Решена хорошо | 80–100 | Зелёный |

Границы применяются включительно: 50 — нормально, 80 — хорошо. Это начальная
аналитическая шкала, а не утверждённые экспертами пороги грейда. Длина сегмента
полосы соответствует доле результатов; при наведении и фокусе отображаются
количество и процент. Текстовые значения доступны без различения цветов.
Пустая группа не выглядит как 100% плохих ответов.

## Показатели

Распределения отдельно показываются по целевому уровню попытки и независимой
метке подготовки. Целевой грейд не служит доказательством уровня кандидата.
В данных платформы независимая метка — грейд той же специализации, подтверждённый
до начала рассматриваемой сессии; грейд этой сессии не используется.

Для каждой пары грейдов считаются две разницы долей:
«нормально или лучше» и «хорошо». Обе группы сравниваются по одинаковым порогам
старшего уровня. Пример: хорошо решают 80% middle и 30% junior → разница 0,5,
или 50 процентных пунктов. Отрицательная разница — повод исследовать задание,
не автоматическое основание исключить его.

Исправленная корреляция задания с общим результатом — коэффициент Пирсона между
баллом за выбранное задание и средним баллом **остальных** этапов сессии.
Само задание исключается. Для референса исключаются все этапы выбранной группы.
Один этап не даёт пары для корреляции; постоянные баллы дают отдельный статус,
а не искусственный ноль. Сравнение не корректирует различия грейдов или сложности
вариантов и не доказывает причинность.

Минимум группы по умолчанию — 10 независимых профилей (настраивается от 5).
До этого разницы / корреляция остаются неопределёнными. Этот минимум служит
индикатором объёма, не гарантией статистической значимости или калибровки.

## Источники и API

`POST /assessment/v1/task-analytics/report`:

- `scope`: `task`, `reference_version` или `reference_family`;
- `scope_id`: UUID редакции контента, версии референса или семейства;
- `task_key`: только для конкретного задания;
- `since` / `until`: даты с часовым поясом, начало включительно, конец исключён;
- `scale.by_grade`: пороги всех четырёх грейдов;
- `scale.minimum_group_size`: минимальная группа.

Используются закреплённые оценки из доказательств завершённых сессий Assessment;
решение апелляции заменяет исходное. Один профиль даёт последнее пригодное наблюдение
в выбранной единице анализа. Технические сбои и отсутствующие баллы исключаются.
Privacy и доступность проверяющего проверяются при расчёте. Ответ содержит только
агрегаты; кандидатские идентификаторы, ответы, скрытые тесты и контакты не выдаются.
Задания компаний в этот общий отчёт не входят. Период ограничен 366 днями;
если в периоде больше 5000 завершённых решений, нужно сузить его — частичная
выборка не выдаётся за полную. Источник текущих результатов маркируется `live_demo`.

`POST /assessment/v1/task-analytics/simulate` принимает до 5000 наблюдений:

```json
{
  "label_source": "synthetic",
  "reason": "Проверка расчёта на синтетических профилях",
  "observations": [
    {"profile_key": "profile-1", "target_grade": "junior", "independent_grade": "junior", "score": 40, "rest_score": 50},
    {"profile_key": "profile-2", "target_grade": "junior", "independent_grade": "middle", "score": 90, "rest_score": 85}
  ]
}
```

`label_source=expert` обозначает экспертную выборку, **заявленную оператором**;
API не подтверждает происхождение меток. Ключи профилей должны быть обезличенными
и уникальными. `rest_score` — средний результат остальных заданий, без анализируемого.
Проверочная выборка и отчёты не сохраняются; ответы имеют `Cache-Control: no-store`.
Результаты симуляции не попадают в калибровку или профиль кандидата.

Для генерации можно сравнивать конкретную версию референса и всё семейство,
но разные версии / варианты не объявляются психометрически эквивалентными.
Для исследований лучше сначала сравнивать фиксированную версию и единый режим
оценивания. Реальный test–retest и измерение стабильности присвоения грейда —
отдельный эксперимент, эти показатели его не заменяют.
